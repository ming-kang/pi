# Cached compaction

The bundled `cached-compaction` extension replaces summary generation for manual `/compact` and automatic threshold compaction. Pi still owns the cut point, session persistence, recent-message retention, and context rebuilding.

Instead of flattening the older messages into a new summarizer prompt and truncating each tool result, the extension sends the current prepared conversation plus one user message asking for a structured checkpoint. This lets the provider reuse its prompt cache and lets the summary model read the complete tool output that was present in the conversation.

Caching is an optimization, not a prerequisite. The extension does not estimate cache expiry or adapt requests to individual providers. A cold cache can make this request more expensive than native compaction, but produces the same kind of checkpoint without a separate provider-specific path.

## Summary boundary

The extension uses Pi's `firstKeptEntryId` unchanged. Because the summary model also sees the retained recent messages, its instruction quotes the first retained message as `<kept-start>` and explicitly excludes that message and everything after it from the summary. Repeated opening text is identified by its occurrence counting backward from the end. If no usable text or tool-call boundary exists, native compaction runs instead.

The summary keeps Pi's Goal, Constraints & Preferences, Progress, Key Decisions, Next Steps, and Critical Context sections. Optional `/compact [instructions]` focus is appended to the instruction. Read and modified file lists are computed from session operations and previous compaction details rather than generated by the model.

## Fallbacks

- Overflow recovery always uses native compaction because the complete context has already exceeded the model window.
- A missing boundary, request failure, empty summary, tool call, or output-length stop falls back to native compaction.
- Cancelling the summary cancels that compaction without starting a second native summary request.
- Branch summarization through `/tree` is unchanged.

Native compaction accepts the same native file-list shape in extension-provided compaction details, so alternating between cached and native compaction does not reset file history.

## Result card

A successful cached-path compaction adds a persistent display-only card after the summary:

```text
Cached compaction · manual
Cache 641.2k/648.8k (98.8%) · output 2.8k · 18.4s
```

Automatic compaction is labelled `automatic`. The cache figures are the response's actual `cacheRead` divided by `input + cacheRead + cacheWrite`; the card also shows output tokens and elapsed time. It contains no cost estimate and never enters model context. Native fallback adds no card.

The extension registers no commands or settings.
