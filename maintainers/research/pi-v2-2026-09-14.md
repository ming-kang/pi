**Pi v2 / Pico 迁移观察，2026-09-14**

本页只保留后续同步需要的判断。当前构建与职责约定见 [Architecture](../architecture.md)，已实施调整见 [Changelog](../../CHANGELOG.md)。正式采纳仍只从上游 release tag 进行。

观察固定在 `main` 的 `71dca871bc80b6bc97be37f0ca3189399d651fff`、`pico` 的 `9b2aff2c5bf5e6c11a79ba0e6fd1b36a9e03eef1`，以及草稿 PR #9548 的 `f4d138b1ac39e9f50a42feb11b2f58919c25904c`。当时最新 release 为 v0.85.1。旧 dev 已通过 [#8963](https://github.com/earendil-works/pi/pull/8963) 合入 main；本地遗留的 dev 引用不能代表当前方向。

**目前不应整体移植 Pico。** `src/harness/pico/` 只有类型、事务和内存存储等基础代码；Pico3 的完整原型仍在文档 zip 中。[Hardening handoff](https://github.com/earendil-works/pi/blob/9b2aff2c5bf5e6c11a79ba0e6fd1b36a9e03eef1/packages/agent/docs/pico/v3/hardening-handoff.md) 明确要求先加固和独立复审，暂不整合。文档中的 Pico v2/v3 是方案迭代编号，不是发布日期承诺。

最新 [plugins](https://github.com/earendil-works/pi/blob/9b2aff2c5bf5e6c11a79ba0e6fd1b36a9e03eef1/packages/agent/docs/pico/v3/plugins.md) 和 [view/events](https://github.com/earendil-works/pi/blob/9b2aff2c5bf5e6c11a79ba0e6fd1b36a9e03eef1/packages/agent/docs/pico/v3/view-and-events.md) 在重叠处优先于较老设计。方向是将执行、持久化、恢复、取消和子对话下沉到 agent-core，UI 消费 ConversationView，功能按 session/presentation facets 装配。尚不能把提案当成已发布 API。

| 功能 | 后续迁移判断 |
| --- | --- |
| Background | 准备让上游 task/job 接管执行底层；保留管理 UI、完成后继续、限额及统计策略。先验证原地 detach、timeout、取消和分支生命周期等价性。 |
| Subagent | 用 owned conversation 替换逐个 AgentSession 的 worker 后端；保留 profile、整批 preflight、并发门限、整组取消和报告顺序。 |
| BTW | 保留临时内存语义。持久 child 不满足“不写 JSONL、不进 tree、关闭即丢弃”；快照、禁工具执行和输入路由需要独立验证。 |
| Question / Todo | 保留交互和领域模型。未来复用 memo/dialog 与 rewindable namespace；harness task 不能替代待办清单。 |
| Provider | 保留编辑器；认证、discovery 和配置写入属于有权限的 session/host，presentation 使用专门契约。 |
| Statusline / 工具呈现 | 保留视觉规则及 parent CTX/CH 与 child usage 的区分，逐步改为消费新 view。 |
| Web Search / DeepWiki / 主题 / Windows 修正 | 没有等价替代证据；跟随公开接口迁移，平台修正逐项复现后再退休。 |

Background 的三个关键差距：

- 上游 job 的 `notify: true` 写入被动 `pi.notice`，不等价于本发行版在安全 idle 边界自动启动主代理回合及持久化后确认投递。
- assistant usage / `pi.usage` 是计费事实，尚无等价的父子整组聚合、去重与分支统计契约。terminal task 从 live view 移除，也不等于 `/bg` Finished 历史已经实现。
- durable task 不保证进程跨重启恢复；ProcessHost 承担进程事实，unknown 后 rerun 可能重复效果。reload 的 suspend/reopen 与当前运行时清理也不是同一语义。

更近的兼容目标是 [草稿 #9548](https://github.com/earendil-works/pi/pull/9548)。它增加 system-role 消息和 prompt/tool checkpoint，修改结构化 `before_agent_start` 输入，移除 tool-result `addedToolNames` 与旧 deferred-loading 字段。采纳含最终实现的 release 时，需要一起核对：

- BTW 的消息 role 过滤、token 估算和缓存前缀，避免 prompt/tools 重复注入或丢失。
- Background 自动回合的 prompt/tool 状态、nextTurn 排序与投递确认。
- Subagent 的提示词、实际工具集合和禁止嵌套/后台规则。
- Provider 表单与 model-config 中的 `deferredToolsMode`、`supportsToolReferences` 及替代字段。
- compaction、树导航与自定义历史记录的重建。

开始 Pico 迁移前，应看到实现进入源码及 CI、正式 npm 导出和 coding-agent 接线、稳定工具/watch/reload 契约，以及 Windows host 与历史迁移的明确支持。继续消费上游发布包，保持单个 @astralyn/pi；不复制原型，也不另建通用兼容框架。
