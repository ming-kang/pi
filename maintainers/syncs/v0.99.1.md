# Upstream v0.99.1

Adopted `earendil-works/pi` release `v0.99.1` from the recorded `v0.87.1` baseline on the standalone `sync/upstream-v0.99.1` branch. The root package remains `@astralyn/pi@0.87.6`; publication and versioning are separate.

## Adoption decisions

- Adopt MCP configuration, stdio/HTTP transports, OAuth, resource tools, `/mcp`, and CLI management; codemode and tool search; nested tool execution and usage accounting; virtual models and classifier/image APIs; provider stream events; RPC input dispositions; system themes and color APIs; session persistence, clipboard, package-management, and performance fixes.
- Consume exact published `@earendil-works/*@0.99.1` dependencies. Add `pi-codemode`, `pi-mcp`, and `quickjs-wasi@3.6.2` as production dependencies; Client/Protocol/Server remain development-only. Adopt Vitest 4.1.11. Keep the standalone TypeScript 5.9.3 and tsx source runner; adopt ES2024 as the target/library without monorepo tooling.
- Adapt Tasks supervision to retain failure status while returning structured shell results for non-zero exit codes. Completed shell output is capped at 1 MiB for scripts; model-facing limits are unchanged. Background handoffs return `{ task_id, status }` rather than pretending a process has completed. Cancellation, timeout, persistence, delivery, and history quotas remain distribution-owned.
- Keep context snapshots, configurable keys, validation hints, distribution identity, fullscreen defaults, and the marker-and-rail tool shell. Port full-argument expansion into the distribution fallback renderer. The upstream replacement tool-execution component remains dropped; its only new delta in this window is argument presentation, now ported.
- Resolve percentage compaction budgets against physical model windows under virtual routing. Preserve ice-cream HTML export transparency and foreground fallback while adopting upstream concrete theme colors and the generated system theme.
- Keep extensions independent. MCP uses the public event bus to identify the registered codemode/tool-search implementations, including inline SDK factories, without importing their internals. Codemode keeps its own domain-neutral ranker. Runtime imports are static under repository policy; workers and WASM are initialized on execution.
- Adapt the Node bundle to the exact release strategy: emit codemode's worker beside its config chunk, include Meta and OpenAI ChatGPT OAuth flows, and check installed pi-ai's lazy OAuth declarations against bundle entries. Keep `PI_BUNDLED_NODE` and the experimental output exclusions.
- Keep distribution-owned documentation. Port factual changes to existing usage, settings, extension, model/provider, SDK/RPC, theme, security, and session-format pages; register the new MCP and virtual-model pages. Upstream `cli.md`, `configuration.md`, and `rpc-commands.md` remain folded into existing pages.
- Do not adopt `test/model-catalog-protocol.test.ts`: it tests pi.dev's monorepo deployment script, which this distribution does not own or ship. Existing remote-catalog client tests remain adopted. Adapt MCP CLI tests to a local stdio fixture instead of importing a sibling monorepo package's test fixture. Dropped install-lock files remain inapplicable to this standalone package.
