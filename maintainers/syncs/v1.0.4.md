## Packaged-install fixture adaptation

Upstream v1.0.4 calls `options.getToolGuidelines()`, which the codemode extension wires to `pi.getAllTools()`, on every script execution. Executing a codemode tool therefore requires a session-bound extension runtime; `test/fixtures/package-bundle-runtime.mjs` executed the tool directly from the resource loader and began failing with `Extension runtime not initialized`. Upstream has no such usage or test, and the SDK path cannot inject a stream function, so the fixture now drives scripts through the public `CodemodeSandbox` + `loadQuickJSWasm` pair the tool itself uses, and additionally spawns the **bundled** worker from a `data:` URL (a `URL` object, as the release runtime does). That check is stronger than the replaced one: the in-process execute ran in an unbundled Node process, so it never spawned the bundled worker, while the data: URL load fails if the bundler inlines a `createRequire` banner or `import.meta`, which is the distribution's own build adaptation.

## Interactive verification

Added a `highlight` prompt to `test/fixtures/offline-provider.ts` that streams a fenced Python block with a multiline docstring and comment. In the pseudo-terminal the pty cannot read terminal colors, so the session runs on the system theme (`syntaxString` `#008000`, keywords `#000080`). `tui-test highlight text "docstring line two" --fg "#008000"` passes on both docstring lines, and a `def clamp --fg "#008000"` control does not match, so a broken `--fg` cannot pass the check. Reverting the `syntax-highlight.ts` fix locally reproduced the bug (the second docstring line carried no color) and confirmed the check catches it; the fix was restored afterwards. The check and its rationale are recorded in [Interactive testing](../interactive-testing.md).
