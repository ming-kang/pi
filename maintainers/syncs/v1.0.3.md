# Upstream v1.0.3

Adopted `earendil-works/pi` release `v1.0.3` (`d78dc83d633229d12f8b79631384c4c2717c399f`), from the recorded `v1.0.2` baseline. Synchronization started from `35ae90b94a3d27d1c98c1dcb1de62bd28ba34b0e` on `sync/upstream-v1.0.3`. The root package stayed at `1.0.3` during synchronization; the owner then requested publication as `@astralyn/pi@1.0.4`.

## Adoption decisions

- Adopt the centralized output-file helpers (`src/utils/output-files.ts`) in the bash executor, the output accumulator, the MCP resource saver, and the codemode spill and image paths. All output files now live in the OS temp directory with mode `0o600`, so truncated tool output, binary MCP resources, and codemode images are readable only by the user.
- Adopt codemode `image()` saving each image to a temp file, with a text label naming the path before the image, deduplicating repeated images and keeping a failed write in the label. Port the three factual changes into `docs/codemode.md`.
- Adopt the Azure provider rename (`azure-openai-responses` → `azure`) through pi-ai `1.0.3` and the merged `src/core/model-resolver.ts`; the `azure-openai-responses` API tag is unchanged, so the `/provider` API lists, compat fields, and API-level documentation stay as they are. Update the `auth.json` key table and the Azure section in `docs/providers.md` with the rename and the new Foundry Chat Completions deployments (`azure/deepseek-v4-pro`).
- Adopt install-change detection (`detectInstallChange`), the once-resolved QuickJS wasm path, and the in-memory codemode worker for `bundled-node`, with the restart warning wired into the interactive error paths.
- Adopt the dead-terminal fix: stdin now carries the terminal error listener, `ENOTTY` joins the dead-terminal codes, and `uncaughtCrash` exits through `emergencyTerminalExit` before recording a crash.
- Adopt the Home/End routing change (editor cursor always; transcript top/bottom on `Ctrl+Home`/`Ctrl+End`) through pi-tui `1.0.3`, and port it into `docs/keybindings.md`, including the fullscreen precedence table.
- Keep `install-lock/` dropped. Upstream's `scripts/build-coding-agent-bundle.mjs` changed in this window: the codemode worker is now emitted in its own esbuild pass without the createRequire banner and validated to import only Node builtins, because `getCodemodeWorkerSpecifier()` spawns it from a `data:` URL. Adopt the same strategy in the distribution's own `scripts/build-bundle.mjs`, which previously bundled the worker with the banner; a banner check joins the builtin-import check, since the banner stays in the output even when nothing calls `require()`.
- Examples take upstream's release version bumps only. `package.json` pins advance through npm; `CHANGELOG.md` is rewritten as distribution prose.

## Conflict resolutions

- `src/core/tools/output-accumulator.ts`: kept the fd-based `persistFromStart` deviation and adopted `createOutputFileStream` for the streaming path; the deviation's constructor now takes its path from the shared helper, so `src/utils/output-files.ts` exports `createOutputFilePath` (registered under `background-execution`).
- `src/extensions/codemode/execute.ts`: kept the distribution's `./search.ts` tool-search import next to the new `../../utils/output-files.ts` import.
- `src/modes/interactive/interactive-mode.ts`: kept `hotkeysTaskSection` next to upstream's extended dead-terminal error codes.

## Dependency review

All ten direct `@earendil-works/*` packages and transitive `pi-telemetry` advance from `1.0.2` to `1.0.3`; resolutions and integrity hashes change only for those eleven packages, with no dependency scope, installation script, or external dependency change. Upstream added no new direct dependency; the nested `brace-expansion` pin from earlier releases still lives in this package's existing override, so nothing else moved.

The requested upstream release was younger than the two-day default age. Resolution and installation used command-scoped `--min-release-age=0`, and package verification used `PI_PACKAGE_ALLOW_FRESH=1`. The shrinkwrap was regenerated with the repository's npm `11.15.0`. `node_modules/.package-lock.json` was stale after the first install and was removed before reinstalling, per the recovery procedure in [Dependency maintenance](../dependencies.md); declared, locked, and installed versions then agreed.

`npm audit` reports the same five high-severity entries in the unchanged development-only `shx` chain as the previous synchronization; production packages are not in that chain.
